## 1. 概述

### 1.1 范围

本文档覆盖博客系统的前端：React SPA 的页面与路由、组件体系、状态管理、数据请求、认证交互、UI 规范、SEO / 安全 / 性能设计，以及**从脚手架到上线的循序渐进实施路径**（第 9 章）。

### 1.2 分期策略

**一期只有"游客 + 管理员"两种身份**；注册用户相关页面二期实现，但目录与路由位置一期预留。

| 角色 | 一期可访问页面 | 二期新增 |
|---|---|---|
| 游客 | 前台全部页面（首页/详情/归档/搜索/关于）；评论区**可发表**（可选填昵称，发表后进待审核，通过后公开可见） | 登录、注册、找回密码 |
| 管理员 | + /login、/admin/* 后台全部页面 | + 用户管理页 |
| 注册用户 | ——（一期不存在） | 发表评论/删除自己的评论、个人中心 |

### 1.3 与后端的契约要点（必须遵守）

- 统一响应包装：`{ code: number, message: string, data: T }`，**HTTP 状态码恒为 200**，业务成败看 `code`（0 为成功；40001 参数错误；40101 登录失败；40102/40103 token 问题；40401 不存在；42901 触发限流（待实施，见后端 doc/ratelimit.md）；50000 服务器错误）。
- 接口路径前缀 `/v1`，公开接口如 `GET /v1/articles`、`GET /v1/articles/:slug`、`GET /v1/site/config`；需登录的如 `POST /v1/auth/login`、`/v1/admin/*`（JWT：`Authorization: Bearer <accessToken>`）。
- 一期登录响应：`{ accessToken, refreshToken: "", expiresIn }` —— **refreshToken 一期为空串**，刷新机制二期再启用（见 5.2）。
- 资源命名为 **article**（不是 post）；**没有标签（tag）功能**；搜索是列表接口加关键词参数兜底。
- JSON 字段全部驼峰（publishedAt、views、coverUrl 等）。

## 2. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 框架 | React 18 + TypeScript | 学习目标框架；TS 与 Go 的静态类型思维一致 |
| 构建工具 | Vite | 启动快、配置简单、社区主流 |

| HTTP 客户端 | fetch 封装（二期可换 TanStack Query） | 学习阶段先理解原理 |

## 4. 组件与 Hooks

### 4.1 核心组件清单（按实现的先后顺序排列，与第 9 章对应）

| 组件 | 职责 |
|---|---|
| `Loading / Empty / ErrorState` | 三态组件，所有数据页复用，**最先做** |
| `Pagination` | 分页器 |
| `ArticleCard` | 列表页文章卡片（封面、标题、摘要、日期、阅读量） |
| `MarkdownRenderer` | react-markdown 封装：GFM、代码高亮、图片懒加载、外链新窗口、**禁用原始 HTML** |
| `Toc` | 详情页目录，解析 heading 生成锚点，滚动高亮 |
| `CommentList` | 评论展示（仅展示已通过评论；后端返回扁平列表，前端按 `parentId` 组树） |
| `AuthGuard` | 路由守卫：一期只判"是否登录"，props 预留 role 位 |
| `AdminLayout` | 后台外壳：侧边栏 + 顶栏 + Outlet |
| `MarkdownEditor` | 写作页：textarea + 工具栏 + 分屏预览 |
| `CommentForm` | 评论发表框（游客可用，可选昵称；提交成功后提示"已提交，待审核"） |

### 4.2 自定义 Hooks

| Hook | 职责 |
|---|---|
| `useFetch<T>` | 数据请求三态（loading / error / data），卸载自动取消（AbortController） |
| `useDebounce` | 搜索输入防抖（300ms） |
| `useAuth` | 登录态读取、login/logout 动作 |
| `useTitle` | document.title 管理（SEO 基础） |

## 5. 状态管理与认证交互

### 5.1 Zustand Store 划分

- `useAuthStore`：accessToken（**仅存内存**）、当前管理员信息、login/logout
- `useThemeStore`：深/浅色模式（localStorage 持久化）
- 服务端数据**不进全局 store**，由 useFetch 在组件内管理，避免过度设计

### 5.2 认证交互流程

**一期（仅管理员，无 refresh）**

```
登录:    POST /v1/auth/login ──► code=0 则 accessToken 存入 useAuthStore（内存）
请求:    client.ts 自动附带 Authorization: Bearer <accessToken>
40103:   token 无效/过期 ──► 清空登录态 ──► 跳 /login?redirect=<原路径>
刷新页面: 内存 token 丢失 ──► 回到游客态，管理员需重新登录（一期的已知取舍）
登出:    清空 store（后端 Logout 接口一期为简化实现）
```

**二期升级（设计预留，届时实现）**

```
RefreshToken: 后端发 httpOnly Cookie；进入应用先调 /v1/auth/refresh 恢复登录态
请求 401:    client 拦截 ──► 静默 refresh（单例 Promise 锁防并发）──► 重放原请求
OAuth:      /login 点击 GitHub ──► 后端 302 ──► /oauth/callback 取 code 完成登录
```

### 5.3 类型契约（src/types/）

与后端 .api 的 type 一一对应（以下与后端实现逐字段对齐）：

```ts
interface ApiResponse<T> { code: number; message: string; data: T }

interface ArticleSummary {
  id: number; title: string; slug: string; summary?: string;
  coverUrl?: string; views: number; publishedAt: string;   // RFC3339 带时区
}
interface ArticleDetail {
  id: number; title: string; slug: string; content: string;
  coverUrl?: string; views: number; publishedAt: string;
}
interface ArticleListResp { list: ArticleSummary[]; total: number }

interface LoginResp { accessToken: string; refreshToken: string; expiresIn: number }
interface ProfileResp { username: string; nickname: string; avatarUrl?: string }

// 评论：后端返回扁平列表（无分页），前端按 parentId 组树；parentId 缺省/0 为顶层
interface CommentItem {
  id: number; parentId?: number; nickname: string; avatarUrl?: string;
  content: string; createdAt: string;
}
interface CommentListResp { list: CommentItem[]; total: number }
// 发表：POST /v1/articles/:slug/comments，body { nickname?, content, parentId? }
// 游客发表后进待审核（status=0），公开列表只返回已通过评论

interface SiteConfig { siteTitle: string; icp?: string; githubUrl?: string }
// User（注册用户）类型二期补充
```

## 6. UI 规范

- 深浅双主题，默认跟随系统 `prefers-color-scheme`
- 主色调：中性灰底 + 单一强调色；阅读页正文最大宽度 720px，字号 16~18px，行高 1.8
- 响应式：移动端 < 640px 单列；桌面 ≥ 1024px 双列带侧栏
- 所有数据页面必须覆盖 loading / empty / error 三态

## 7. 前端非功能性设计

### 7.1 SEO

- 文章 URL 用 slug；每页 `useTitle` 设 title；详情页注入 description / og 标签
- RSS、sitemap 由后端输出，前端页脚放入口
- SPA 的 SEO 局限是已知取舍；二期可评估迁 Next.js（SSR/SSG）

### 7.2 安全（前端侧）

| 风险 | 对策 |
|---|---|
| XSS | MarkdownRenderer 禁用原始 HTML；评论纯文本转义展示 |
| Token 窃取 | accessToken 只存内存，不落 localStorage |
| 敏感代码 | 后台路由 React.lazy 懒加载，游客不下载后台代码包 |

### 7.3 性能

- 路由级代码分割（React.lazy），首屏只加载前台
- 图片懒加载；列表页缩略图，原图仅详情页加载
- Nginx 缓存静态资源（hash 文件名 immutable）+ Gzip/Brotli
- 搜索输入防抖；列表请求随分页复用

## 8. 构建与部署

- **全 Docker 化**：多阶段构建（node 阶段 `npm run build` → 产物交给 Nginx 镜像托管），无独立 Node 运行时
- **不走镜像仓库**：与后端同策略——服务器 `git pull` 后本地构建（`docker compose up -d --build`）。**注意前端 `npm run build` 内存峰值常超 1.5GB，2C2G 服务器务必先配 1~2GB swap**；若频繁 OOM 再回退到 GitHub Actions 构建镜像的方案
- SPA history 模式，Nginx 配 `try_files $uri /index.html` 兜底
- 开发环境：Vite dev server 配 proxy 把 `/v1` 代理到 `http://localhost:8812`，免跨域

## 9. 循序渐进实施路径（一期）

> 每一步都建立在前一步之上；**每步完成的标准是"能跑、能肉眼验证"**，再进下一步。预计对应学习计划第 2~7 周。

### 阶段 A：地基（不碰后端）

| 步骤 | 任务 | 验收标准 |
|---|---|---|
| A1 | `npm create vite@latest web -- --template react-ts`，配好 Tailwind | 默认页能跑，写一个 Tailwind 类名生效 |
| A2 | 装 react-router-dom，搭路由骨架：5 个前台路由 + /login + /admin/* 全部指向占位组件 | 手敲 URL 能切页，地址栏变化正常 |
| A3 | 写 `types/`（按 5.3）和 `api/client.ts`（fetch 封装：解包 code≠0 抛错、自动带 token） | client 能调通任意公开接口并拿到 data |
| A4 | 写 `Loading / Empty / ErrorState` 三态组件 + `useFetch` hook | 用一个假延时数据源演示三态切换 |
| A5 | 前台布局：顶栏（站点名来自 /v1/site/config）+ 页脚 + 主题切换（useThemeStore） | 明暗主题切换无闪烁，刷新后保持 |

### 阶段 B：前台页面（接真实 API）

| 步骤 | 任务 | 验收标准 |
|---|---|---|
| B1 | 首页：ArticleCard + 列表 + Pagination，接 `GET /v1/articles` | 真实数据渲染，翻页正常，空列表显示 Empty |
| B2 | 详情页：MarkdownRenderer + 代码高亮，接 `GET /v1/articles/:slug` | 渲染一篇真文章，代码块有高亮，XSS 测试（文中塞 script 不执行） |
| B3 | Toc 组件 + 详情页打磨（720px 正文、行高、useTitle） | 目录点击跳转、滚动高亮当前节 |
| B4 | 归档页：复用列表接口，前端按年月分组 | 时间线正确分组排序 |
| B5 | 搜索页：useDebounce + 列表接口关键词参数，URL 同步 ?q= | 输入防抖生效，刷新 URL 能还原搜索 |
| B6 | 关于页：读 site config | 后台改配置后前台刷新生效 |
| B7 | 评论区：CommentList 接评论列表接口 + CommentForm 游客发表（可选昵称） | 评论树按 parentId 正确嵌套；游客发表后提示"已提交，待审核"，刷新后未审核评论不展示 |

### 阶段 C：认证与后台

| 步骤 | 任务 | 验收标准 |
|---|---|---|
| C1 | useAuthStore + useAuth；登录页表单接 `POST /v1/auth/login` | 错误密码显示 40101 的 message；成功跳 redirect 或 /admin |
| C2 | AuthGuard 包住 /admin/*；未登录踢回 /login?redirect= | 直接访问 /admin 被拦截，登录后跳回目标页 |
| C3 | AdminLayout + 仪表盘（统计数据接口） | 侧边栏导航正常，数字真实 |
| C4 | 文章管理页：表格列表 + 上下线 + 删除（二次确认） | 操作后列表刷新，前台同步可见变化 |
| C5 | 写作页：MarkdownEditor 分屏预览 + 保存（新建/编辑复用） | 能发文并在前台看到；slug 冲突有报错提示 |
| C6 | 封面上传：接 `/v1/admin/upload`（RustFS 预签名或直传） | 图片上传成功，详情页能显示 |
| C7 | 评论管理页：审核通过 / 标垃圾 / 删除 + 管理员回复（复用 CommentForm） | 游客待审核评论可审核通过，通过后前台可见；管理员回复在前台正确显示 |
| C8 | 站点设置页 + 修改密码页 | 配置保存生效；改密后旧 token 失效需重登 |

## 10. 风险

| 风险 | 说明 | 对策 |
|---|---|---|
| SPA 对 SEO 不友好 | 博客依赖搜索流量 | 一期做好 meta/语义化；二期迁 Next.js |
| 刷新丢登录态 | 一期 token 只存内存 | 已知取舍，文档明示；二期 refresh cookie 解决 |
| 编辑器复杂度失控 | Markdown 编辑器易陷细节 | 一期 textarea + 分屏预览，进阶编辑器进 backlog |
| 范围蔓延 | 前台视觉打磨易超时 | 严守阶段 A~D 边界，UI 迭代进二期 |
